# vendor-curator

取引先シャード（`shards/vendors/{Name}.md`）のキュレーション方針。

## 継承する原則

`[SKILL.md](SKILL.md)` の writer 原則を継承。

## 取引先固有の方針

### 1. 評価軸を固定して記述

3軸を一貫して記録：

- **品質**: 仕上がり、不具合率、是正対応の早さ
- **対応**: コミュニケーション、即応性、提案力
- **価格**: 競合比、見積精度、交渉余地

各軸を「○○案件で△△だった」という**具体例ベース**で記述する。漠然とした「良い/悪い」は禁。

### 2. 実績は案件 wikilink で紐付け

```markdown
## 実績
- [[projects/MaruMaruMansion]] (2026): 排煙設備一式、納期厳守、品質良好
- [[archive/projects/BatsuBiru]] (2025): 配管工事、図面解釈ミスあり
```

### 3. 担当者ノート

法人評価とは別に、個別担当者のノート：

```markdown
## 担当者
### 三角次郎（営業）
- 初動が早い、ただし詳細詰めが甘い時あり
### 四角三郎（現場監督）
- 現場対応力高、変更対応に強い
```

### 4. 警告メモ

過去のトラブル・注意事項は明示的に：

```markdown
## 注意事項
- ⚠️ 2025-12 配管材の代替提案でグレード変更あり、要確認
```

## absorb の流れ

1. triage で `vendors/<slug>` 主シャード + 副タグを取得
2. 既存記事の評価軸節を更新
3. 新規実績は wikilink 付きで「## 実績」に追記
4. 評価が変わるイベントがあれば「## 評価」を rewrite（append しない）
5. checkpoint: `_index.md` 更新

## 反パターン

- ❌ 評価を漠然と「対応良い」と書く
- ❌ 実績の案件 wikilink を省く
- ❌ ネガティブ情報を漂白する
